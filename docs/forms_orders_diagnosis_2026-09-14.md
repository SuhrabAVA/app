# Диагностика расхождений склада форм и заказов — 14.09.2026

Проверены текущий локальный код и рабочая база Supabase jwvzuepqqtdprmsayouf: 280 заказов, 1931 форма, связи PDF, краски заказа, ограничения и триггеры. Это сквозная диагностика подсистемы «формы → заказы → файлы → отображение», а не заключение об исправности всех остальных подсистем проекта. SQL выполнялся только на чтение. Код приложения и рабочие данные не изменены. В рабочем дереве уже присутствовало много чужих изменений; выводы о коде относятся к текущему дереву, версия установленного приложения отдельно не проверялась.

## Главная причина примера Rommi

Заказ 57ddddb9-eaf0-4b9c-8d4f-095c737f13db совпадает со скриншотом: Rommi, 09.09–25.09.2026, В-образный пакет, 20 000, 29×8×3.5.

| Поле | Заказ | Склад, нужная форма |
|---|---|---|
| id | 57ddddb9-eaf0-4b9c-8d4f-095c737f13db | 84ad0235-fecc-4911-bfe6-16ed110a2431 |
| номер | 1 | 1671 |
| серия | Rommi | Rommi  doner 1,5 |
| код | Rommi  doner 1,5 1671 | NULL |
| прямая ссылка form_id | NULL | — |

В edit_order_screen.dart:4395–4406 строковая ветка сохранения старой формы:
- извлекает номер через RegExp(r'\d+').firstMatch(code);
- извлекает серию через RegExp(r'^[A-Za-zА-Яа-я]+').firstMatch(code);
- сохраняет всю строку отображения в form_code.

Для «Rommi  doner 1,5 1671» результат: номер 1, серия Rommi, код — вся строка. Это в точности совпадает с тремя полями рабочего заказа. Локальное выполнение того же алгоритма на Dart подтвердило результат: scripts/diagnose_form_reference.dart (exit 0).

В эту ветку можно попасть:
1. При вводе текста без выбора строки справочника: _onFormSearchChanged, строки 434–458, сохраняет свободный текст в _selectedOldForm.
2. При редактировании уже назначенной формы: _startFormEditing, строки 8337–8363, восстанавливает текст, но не строку справочника. Если сохранить без повторного выбора результата, текст разбирается регулярными выражениями.
3. При изменении текста после выбора строки: выбранная запись сбрасывается.

При выборе результата кликом сохраняется _selectedOldFormRow и номер берётся из поля number (строки 8464 и 4386), эта ветка сама по себе номер 1671 в 1 не превращает.

Какие именно действия пользователь совершил в момент повреждения, по текущему состоянию данных установить нельзя. Но дефект воспроизведён, и его результат полностью совпадает с повреждёнными реквизитами заказа.

Карточка order_details_card.dart:1313–1320 предпочитает order.newFormNo и поэтому честно показывает сохранённую ошибочную единицу. Это не просто устаревший экран: неправильный номер уже находится в базе.

## Почему PDF не попал на склад

У заказа есть запись order_files с именем Rommi_doner_29x8x3.5.pdf. У формы 84ad0235-fecc-4911-bfe6-16ed110a2431 записей form_files нет.

storage_service.dart:379 ищет форму сначала по точному code, затем по точным series + number. У нужной формы code=NULL, а серии Rommi с номером 1 нет. Поэтому поиск возвращает NULL. В edit_order_screen.dart:4048 связь PDF создаётся только при assignedFormId != null. Ошибочная ссылка не позволяет выполнить эту ветку.

Форма adika №1 имеет другой id: 22614108-9c85-43c7-a583-98873058c934; её _.pdf имеет source=form. Номер 1 не означает, что Rommi привязан к adika: текущий поиск не использует один номер, а прямой ссылки у заказа нет. В базе есть ещё форма «Тест» №1.

## Системные причины

1. **Ссылка на запись не используется.** В orders существует form_id с внешним ключом на forms(id), но во всех 280 заказах он NULL. OrderModel его не моделирует; _processFormAssignment получает resolvedFormId для PDF, но при UPDATE заказа записывает только номер, серию и код (edit_order_screen.dart:4494). Это позволяет сохранить реквизиты несуществующей формы.
2. **Защита базы обходится текущим способом записи.** Триггеры trg_orders_sync_form_fields и trg_orders_sync_form_no работают на INSERT / UPDATE OF form_id и ничего не исправляют при NULL. Изменение new_form_no, form_series, form_code отдельно не активирует эти триггеры.
3. **Редактирование склада не обновляет заказ.** warehouse_provider.dart:3391–3466 меняет forms и счётчик forms_series, но не реквизиты orders и даже не code при изменении серии/номера. Триггеры forms обновляют только updated_at. Текстовая ссылка может перестать находиться после переименования.
4. **Проверка обязательного блока не проверяет существование формы.** order_required_blocks.dart:73–77 считает блок заполненным даже по hasForm=true. Этот механизм не обнаруживает повреждённую связь.
5. **Сохранение не атомарно.** Заказ сохраняется до отдельной обработки формы и PDF; _processFormAssignment ловит ошибку и возвращает NULL. Частично сохранённое состояние допускается.
6. **Импорт также пишет текстовые реквизиты.** scripts/add_order.py:261–269 записывает номер и серию из входного файла без form_id. Само по себе это не доказывает происхождение дефекта Rommi, но поддерживает общую проблему отсутствия надёжных связей.
7. **Номер не глобально уникален.** В базе восемь номеров встречаются дважды: 1, 520, 1526, 1821, 1836, 1844, 1845, 1846. Среди ограничений forms найдены PRIMARY KEY(id) и UNIQUE(series, code), а не уникальность number. Исправлять ссылки простым поиском «по номеру» опасно.

## Размеры и краски

Размеры в карточке заказа — из orders.product, размеры склада — из forms.size. Они не синхронизируются. Например, форма Rommi №1692 содержит 13*9*5, а заказ a6eb547d-3dcd-4a78-99b5-b79c4e5c32c6 — 9×9×3.5. Это дополнительное фактическое расхождение; без производственного оригинала нельзя определить правильную сторону и нельзя автоматически переписать заказ.

Краски заказа Rommi подтверждены в order_paints: «021 Оранжевый», 6 кг, и «Черный Чёрный», 1 кг. В карточке это 6000 и 1000 г, конвертация соответствует данным. Поле формы colors содержит свободный текст «021  черный» и не является связанным списком красок. По этому тексту нельзя заключить, что оранжевый ошибочен: «021» может обозначать его код. У adika текст colors=«черный пантон», description=«Краски: Тест Красный Красный 5 г» — два независимых текстовых поля, уже противоречивых в самой складской записи.

Необходимо разделить описание печатной формы и расход красок конкретного тиража; количество красок заказа не следует автоматически копировать в общий справочник формы.
